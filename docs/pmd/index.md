# 项目管理文档

## 当前问题

客户通过群聊了解项目进展：在群里问进度、在群里收文件、在群里提问题。信息分散在聊天记录里，难以追溯，双方都靠人工同步。

## 解决方案

做一个信息窗口，把群聊里流动的信息搬到产品里，客户自己就能看到：

- 项目到什么阶段了
- 数据在处理流程的哪一步
- 交付物有哪些、什么版本

业务信息由内部系统直接同步到客户端，不依赖人工在群里告知。

## 信息范围

项目制数据处理服务的业务围绕四个维度展开：项目、商务、数据、资产。前三类分别对应三个岗位的产出，资产是所有岗位的共同交付物。

## 操作边界

当前只做信息展示，客户端内不支持修改、提交、审批。客户如有变更需求，仍通过群聊或电话沟通。

这不是因为"读写不重要"，而是因为当前的核心矛盾是信息不透明，不是操作效率低。先把透明度解决，操作边界根据实际使用情况再定。

## 后续判断

如果出现以下情况，说明当前边界需要调整：

- 客户反复要求在客户端内完成某个操作，且群聊沟通成本明显高于开发成本
- 项目规模增长到人工同步信息成为瓶颈
