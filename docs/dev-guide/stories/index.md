# 用户故事地图

| 用户活动（阶段） | 用户任务（关键节点） | 客户（委托方）责任 | 量潮数据（代理方）责任 | 双方协同要点与产出 |
|---|---|---|---|---|
| 1. 需求探索与评估 | 1.1 初步沟通 | 提供初步业务目标、场景描述与期望。 | 引导需求讨论，提供《客户需求问卷》，介绍服务能力与局限。 | 共同产出：经双方确认的《需求规格说明书》，明确项目范围与验收标准。 |
| 1. 需求探索与评估 | 1.2 提供资料与Demo | 提供真实、代表性的样本数据、文档或Demo。 | 分析资料，基于Demo编写清洗过程伪代码，并与客户确认逻辑。 | 权责流转标志：客户签署确认的伪代码流程或需求文档。 |
| 1. 需求探索与评估 | 1.3 评估与报价 | 确认技术方案是否理解业务意图，审议报价合理性。 | 进行内部可行性评估，提供详细报价单（含定价规则）。 | 协同决策：就技术路径、范围、成本达成共识。 |
| 2. 约定与启动 | 2.1 合同签订 | 审议合同条款（特别是交付、验收、变更、违约责任），支付首付款。 | 拟定合同，明确需求范围、交付物、付款节点、违约责任。 | 核心产出：生效的《商务合同》。关键：合同中明确客户验收时限与延迟责任。 |
| 2. 约定与启动 | 2.2 项目启动 | 指定对接人，准备内部资源。 | 内部资源分配，召开项目启动会，明确内部任务。 | 建立正式沟通渠道。 |
| 3. 执行与监控 | 3.1 定期进度同步 | 按约定周期（如每3天）审阅进度报告，并及时提供明确反馈。 | 主动、透明地定期汇报进度、演示阶段性成果，暴露风险。 | 协同机制：定期站会或进度报告循环。目标：信息对称，及时纠偏。 |
| 3. 执行与监控 | 3.2 问题与风险处理 | 对量潮数据提出的问题与风险，及时响应并共同商讨解决方案。 | 主动识别和预警风险，提出解决方案建议。 | 将已确认的解决方案通过书面形式（如邮件）固化。 |
| 4. 变更管理（可选路径） | 4.1 提出变更请求 | 清晰描述变更内容、原因及期望，理解变更可能带来的影响和成本。 | 评估变更对范围、周期、成本的影响，提供《变更方案与成本评估》。 | 关键规则：所有变更必须书面确认并补签协议。 |
| 4. 变更管理（可选路径） | 4.2 协商与确认变更 | 审批变更方案，按新协议支付费用。 | 执行变更流程，更新项目计划。 | 权责流转标志：双方签署的《变更协议》。 |
| 5. 验收与交付 | 5.1 验收测试 | 对交付的数据实例进行测试验证，确认其符合约定标准，并按时提供验收结论。 | 提交完整交付物及实例供确认，配合客户完成验收。 | 协同产出：客户签署的《最终验收报告》。关键：合同可约定"超期未反馈视为通过"。 |
| 5. 验收与交付 | 5.2 支付尾款 | 根据合同约定及验收结果，按时支付项目尾款。 | 确认尾款到账。 | 项目付款条件完成。 |
| 5. 验收与交付 | 5.3 成果交付 | 接收最终数据，并在约定时间内反馈问题（如有）。 | 在尾款结清后，通过邮件等正式渠道交付全部数据，并启动反馈期。 | 权责流转标志：正式交付邮件发出，且反馈期结束。项目关闭。 |
